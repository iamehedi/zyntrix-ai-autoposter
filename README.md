# 🚀 Zyntrix Studio — AI-Powered Facebook Autoposter

An autonomous, production-ready, GitHub-based AI social media publishing system built for **Zyntrix Studio**, a software, web development, and AI solutions agency.

The system runs completely in the cloud via **GitHub Actions**—requiring zero local machine uptime. It takes topics from a queue, orchestrates a 3-agent CrewAI pipeline powered by **Groq Qwen 3.6**, generates custom 1080×1080 branded tech imagery via **Pollinations AI**, quality-checks the content against brand guidelines, and publishes directly to the **Zyntrix Studio Facebook Page** via Meta's Graph API.

## 🔐 1. Facebook Page Credentials Setup Guide

To enable automated posting to your Facebook Page, you need a **Permanent Page Access Token** and your **Page ID**.

### Step 1: Create a Meta Developer Account & App
1. Go to [Meta for Developers Portal](https://developers.facebook.com/) and log in with your Facebook account.
2. Click **My Apps** → **Create App**.
3. Select **Other** → **Business** as the app type.
4. Set an App Display Name (e.g., `Zyntrix Autoposter`) and complete the creation process.

### Step 2: Configure Graph API Explorer & Request Permissions
1. Open the [Graph API Explorer](https://developers.facebook.com/tools/explorer/).
2. In the top-right corner, select your newly created Meta App.
3. Under **User or Page**, select **User Token**.
4. In the **Permissions** drop-down, add the following required permissions:
   - `pages_manage_posts`
   - `pages_read_engagement`
   - `pages_show_list`
5. Click **Generate Access Token** and approve the permissions modal.

### Step 3: Retrieve Page ID and Page Access Token
1. In Graph API Explorer, run the query:
   ```http
   GET /v20.0/me/accounts
   ```
2. Find your **Zyntrix Studio** Facebook Page in the response data:
   - Note the `"id"` value → This is your `FACEBOOK_PAGE_ID`.
   - Note the `"access_token"` value → This is your temporary `FACEBOOK_PAGE_ACCESS_TOKEN`.

### Step 4: Convert to a Long-Lived / Permanent Page Access Token
Short-lived user tokens expire in 1-2 hours. To generate a long-lived token:
1. Open the [Access Token Tool / Debugger](https://developers.facebook.com/tools/debug/accesstoken/).
2. Paste the user access token and click **Debug**.
3. Click **Extend Access Token** at the bottom to get a 60-day token.
4. Use this 60-day token in Graph API Explorer to make a `GET /me/accounts` request.
5. The Page Access Tokens returned for Pages managed by a Business App will remain valid indefinitely unless password changes or permission revocations occur.

## ⚙️ 2. GitHub Secrets Setup Guide

To run the workflow automatically on GitHub Actions, add your credentials as Repository Secrets:

1. Open your GitHub Repository.
2. Go to **Settings** → **Secrets and variables** → **Actions**.
3. Click **New repository secret** and add the following:

| Secret Name | Description | Example / Required Format |
| :--- | :--- | :--- |
| `GROQ_API_KEY` | API key from [Groq Console](https://console.groq.com) | `gsk_...` |
| `FACEBOOK_PAGE_ID` | Numeric Facebook Page ID | `123456789012345` |
| `FACEBOOK_PAGE_ACCESS_TOKEN` | Permanent Facebook Page Access Token | `EAAG...` |
| `POLLINATIONS_API_KEY` | (Optional) Pollinations.ai API Key | `pk_...` or leave blank for free tier |
| `GROQ_MODEL` | (Optional) Groq model override | `qwen/qwen3.6-27b` |
| `GRAPH_API_VERSION` | (Optional) Meta Graph API Version | `v20.0` |

## 💻 3. Local Setup & Testing

You can easily run and test the autoposter engine on your local computer before deploying.

### Prerequisites
- Python 3.10 or higher installed.
- Git installed.

### Steps

1. **Clone the repository**:
   ```bash
   git clone https://github.com/your-username/zyntrix-ai-autoposter.git
   cd zyntrix-ai-autoposter
   ```

2. **Create a virtual environment**:
   - **Windows**:
     ```powershell
     python -m venv .venv
     .venv\Scripts\activate
     ```
   - **Linux / macOS**:
     ```bash
     python3 -m venv .venv
     source .venv/bin/activate
     ```

3. **Install dependencies**:
   ```bash
   pip install -r requirements.txt
   ```

4. **Configure environment variables**:
   Copy `.env.example` to `.env` and insert your credentials:
   ```bash
   cp .env.example .env
   ```
   Edit `.env`:
   ```env
   GROQ_API_KEY=gsk_your_real_groq_key
   GROQ_MODEL=qwen/qwen3.6-27b
   FACEBOOK_PAGE_ID=123456789012345
   FACEBOOK_PAGE_ACCESS_TOKEN=EAAG...
   POLLINATIONS_API_KEY=
   GRAPH_API_VERSION=v20.0
   ```

5. **Run the autoposter engine**:
   ```bash
   python app.py
   ```

If successful, the script will:
- Read the top topic from `topics.txt`.
- Generate and approve content via CrewAI.
- Download the generated image.
- Post to your Facebook Page.
- Remove the topic from `topics.txt`.

## 🤖 4. GitHub Actions Testing & Daily Automation

### Manual Workflow Execution
You can manually trigger the workflow anytime:
1. Go to your GitHub Repository.
2. Click the **Actions** tab.
3. Select **Zyntrix AI Facebook Autoposter** from the left sidebar.
4. Click **Run workflow** → Select branch `main` → Click **Run workflow**.

### Daily Automatic Schedule
The workflow includes a cron trigger configured for daily posting:
```yaml
schedule:
  - cron: "0 12 * * *"  # 12:00 UTC = 6:00 PM BST (Bangladesh Standard Time - UTC+6)
```

> [!NOTE]
> GitHub Actions cron jobs run on shared runner pools. Scheduled execution may occasionally experience a slight delay (10-30 minutes) during peak GitHub infrastructure load times.

## 📋 5. Topic Queue Lifecycle (`topics.txt`)

- `topics.txt` acts as an automated task queue.
- On each execution, `app.py` reads the **first available non-empty topic**.
- **Atomic Queue Operation**: `topics.txt` is updated **ONLY AFTER** Facebook successfully returns an HTTP 200 upload confirmation.
- If content generation is rejected or image generation fails or Meta Graph API returns an error:
  - The topic **remains in the queue**.
  - The run fails cleanly (exit status `1`).
  - GitHub Actions sends an alert email so you can inspect the issue.

## 🛠️ 6. Troubleshooting & Common Errors

### 1. `Facebook Graph API Error (HTTP 400/401): Invalid OAuth access token`
- **Cause**: The Page Access Token is expired, invalid, or missing required permissions.
- **Fix**: Re-generate the Page Access Token following Section 1 with `pages_manage_posts` permission.

### 2. `CrewAI initialization failed / Groq API error`
- **Cause**: Invalid `GROQ_API_KEY` or `GROQ_MODEL` is deprecated.
- **Fix**: Ensure your key starts with `gsk_` and check active models on [Groq Models Console](https://console.groq.com/docs/models).

### 3. `Pollinations API failed / empty image`
- **Cause**: Temporary image endpoint timeout or network restriction.
- **Fix**: The script will exit status 1 safely without corrupting the topic queue. Re-triggering the workflow will resolve transient API spikes.

### 4. `GitHub Push Error in Workflow`
- **Cause**: Workflow workflow lacks write permissions to commit updated `topics.txt`.
- **Fix**: Go to **Settings** → **Actions** → **General** → **Workflow permissions** → Select **Read and write permissions**.

## 🛡️ 7. Security & Anti-Spam Guidelines

- **Never Commit Secrets**: Ensure `.env` is listed in `.gitignore`. Secrets must only reside in GitHub Secrets.
- **No False Claims**: The Manager Agent automatically screens out misleading statements ("100% guarantee", unverified client reviews, fake awards).
- **No Spamming**: Post volume is controlled via scheduled cron runs (1 post per day maximum recommended).
